# 知微智学免费上线说明

## 正式架构

- 前端：Vercel（免费 Hobby）
- 后端：Vercel Serverless（免费 Hobby，独立项目）
- 数据库、向量检索与私有文件：Supabase PostgreSQL、pgvector、Storage

此方案不需要绑定银行卡，也不依赖 Hugging Face Docker Space。后端采用按需启动的 Serverless 函数；首次请求可能略慢，但没有固定服务器费用。

## 1. 部署后端 Vercel Serverless 项目

从 GitHub 导入 `yangwei251003/zhiwei-ai-learning`，Root Directory 设置为 `backend`。仓库里的 `backend/vercel.json` 会将所有 API 请求路由到 FastAPI 应用。不要把后端和前端导入成同一个项目。

在后端项目的 Production Environment Variables 中填写以下 **新生成且未泄露** 的值：

```text
DATABASE_URL=Supabase Connect 提供的 PostgreSQL URI（sslmode=require）
SUPABASE_URL=https://<project-ref>.supabase.co
SUPABASE_SERVICE_ROLE_KEY=<仅后端可见的 service_role key>
SUPABASE_STORAGE_BUCKET=knowledge-uploads
RAG_BACKEND=supabase
SECRET_KEY=<随机生成的长字符串>
CORS_ORIGINS=https://<前端-vercel-域名>
```

按需添加模型服务的密钥。所有密钥只放在后端 Vercel 环境变量，绝不提交到 GitHub 或前端。部署后访问 `https://<后端域名>/health`，应返回健康状态。

> Vercel Serverless 不应运行 Alembic 启动迁移；请先在 Supabase SQL Editor 执行项目的迁移 SQL，或使用具备数据库连接权限的本地环境执行 `alembic upgrade head`。

## 2. 部署前端 Vercel 项目

再次从相同 GitHub 仓库创建一个 Vercel 项目，Root Directory 设置为 `frontend`。在 Production Environment Variables 中设置：

```text
VITE_API_BASE_URL=https://<后端-vercel-域名>
```

发布完成后，将前端正式域名写入后端项目的 `CORS_ORIGINS`，然后重新部署后端。

## Supabase 必要状态

已启用 `vector` 扩展并创建私有 `knowledge-uploads` bucket 后，还必须应用 `backend/alembic/versions/c1d2e3f4a5b6_add_knowledge_chunks.py` 及此前的全部数据库迁移。浏览器若直接使用 Supabase，只能使用 anon key；`SUPABASE_SERVICE_ROLE_KEY` 永远只保留在后端 Vercel 环境变量中。

## 本地开发

正式部署使用 `backend/requirements.txt`，它不携带大型本地向量模型。需要使用本地 Chroma 模式时，执行：

```text
pip install -r requirements.local.txt
```

## 验收

1. 打开前端 Vercel 域名并注册账户。
2. 发送一条对话，确认流式回复。
3. 在管理后台上传小于限制的 PDF、DOCX、TXT 或 MD，确认能检索。
4. 刷新页面，确认登录态仍有效。
